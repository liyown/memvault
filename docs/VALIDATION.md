# 验收记录

日期：2026-10-15。版本：**0.1.0-preview**。

核心归档、检索、记忆维护、网页和 CLI 已实现并在本机运行。本记录区分自动测试、样本适配、真实接入和未完成的发布门槛；不将预览版标作 1.0。

## 运行环境

- macOS / arm64，Apple M5，10 核、32 GB 内存、SSD。
- Go 1.27.1；Codex 0.158.0；OpenCode 1.18.33。
- Claude Code 客户端当前不可用，有可读取的本地历史。
- 真实资产存放在用户选择的 iCloud 记忆目录；本机索引、凭据和队列保存在应用目录。
- 本机当前归档约 638 个独立会话、33,184 条可识别消息（持续采集，数字会增长）。

## 百万消息性能

固定数据：10,000 会话、每会话 100 消息，中英文混合；本机 SQLite 索引直接构造。该测试衡量查询与页面，不代表百万消息原始档案导入吞吐。

| 指标 | 本机实测 |
|---|---:|
| 热搜索，6 类查询、120 样本，默认时间排序 P95 | 0.474 ms |
| 会话列表与首个会话 100 消息读取 | 4.135 ms |
| 同时归档 2,000 条新增消息时搜索 P95 | 0.199 ms |
| 已有百万消息索引，真实浏览器导航至正文显示 | 130 ms |

完整输出：[performance-macos-arm64.txt](performance-macos-arm64.txt)。通过 `MEMVAULT_PERF=1 go test ./internal/app -run TestMillionMessageSearch -v -timeout 20m` 复现搜索。可选 `MEMVAULT_PERF_BROWSER_RECEIPT` 启动临时本地页面验证入口，需真实浏览器回写 `interactive_ms`；本次记录包含浏览器结果。

首次使用相关度排序时，极常见词曾测到约 1.4 秒 P95；默认时间排序改为索引直接分页后达到上述结果。相关度排序仍允许使用，但不能声称常见词排名已达到 500 ms 目标。四核、16 GB 参考硬件未实测。

一次人工性能收据未及时写入导致等待超时，已改为自动等待并复测通过；未把超时轮次记作通过。

## 仍需完成的 1.0 门槛

1. **macOS 登录后台访问授权**：真实 LaunchAgent 启动时，系统 TCC 日志确认其被阻止访问当前 iCloud 目录。登录项配置保留，已停止反复失败的登录进程；当前由具备访问权限的会话启动后台并正常归档。必须由用户在系统设置亲自授权后重新注册、重登验证，程序不绕过系统权限。当前不能承诺重启后自动运行。
2. **客户端完整闭环**：补齐三个客户端真实新会话、恢复、压缩、结束和跨 agent 接续的验收；Claude 客户端当前未安装，不自动安装。配置存在和事件样本通过单独记录，不冒充运行验证。
3. **其他操作系统**：Linux systemd user、Windows 用户登录启动以及各自路径、权限与浏览器启动需在对应系统验证。
4. **故障与同步压力**：完整强杀矩阵、真实多机器离线同步、长期大档案与损坏注入压力测试。
5. **发布生命周期**：尚无托管的自动更新渠道及签名发布包；当前使用单二进制构建与替换前备份，支持人工恢复旧版本。正式更新失败回滚需发布渠道验收。

以上事项没有通过前，版本保持预览状态。用户自行同步与备份，外部平台及备份中的原件不会由遗忘功能删除。
